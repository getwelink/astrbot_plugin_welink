# astrbot_plugin_welink

把一个**微信个人号**接成 AstrBot 的消息平台。装上之后，AstrBot 的平台列表里会多出一个 `welink`，和 telegram、discord、企业微信这些并列。

**轮询取消息，不需要公网地址。** 家里的树莓派、NAS、docker 容器都能直接用，不用做端口映射，也不用买域名。

---

## 装

需要 AstrBot 4.14.0 或更新的版本。两种装法，任选一种。

**在 WebUI 里装**：插件 → 安装 → 「从链接安装」，填：

```
https://github.com/getwelink/astrbot_plugin_welink
```

**命令行装**：把这个目录放进 AstrBot 的 `data/plugins/`：

```bash
cd data/plugins
git clone https://github.com/getwelink/astrbot_plugin_welink
```

重启 AstrBot，或者在插件管理里点重载。

## 配

到 WebUI 的「平台适配器」里新增一个，类型选 `welink`，填两项：

| 配置 | 说明 |
| --- | --- |
| `base_url` | WeLink 服务地址，例如 `https://你的地址`（会自动补 `/v1`） |
| `api_key` | 控制台里的 API Key，形如 `key_xxx` |
| `account_id` | 用哪个微信实例。**留空会自动选一个在线的** |
| `poll_interval` | 几秒拉一次，默认 3 |
| `poll_limit` | 一次最多拉几条，默认 100，上限 200 |
| `download_image` | 收到图片时换成可下载地址交给模型，默认开 |
| `group_reply_needs_at` | 群里只理 @ 了机器人、或者以唤醒前缀（默认 `/`）开头的消息，默认开 |
| `loop_guard_per_minute` | 同一个会话一分钟内最多触发机器人几次，超过就先暂停 3 分钟不理它，默认 12；填 0 关掉 |

没有 Key 的话，[到这里免费领一个](https://github.com/getwelink/weLink#怎么用起来免费)。

## 能做什么

**收**：私聊和群聊的文字；图片会转成地址交给模型（视觉模型可以直接看）；语音、视频、文件、表情、链接、小程序卡片会以 `[语音]` 这样的标签送进去，让模型知道来了东西而不是空一轮。

**发**：文字、图片、语音、文件。群里 `@` 某人会真的 `@` 到。

**主动发**：支持 `send_by_session`，插件和定时任务可以直接往某个会话推消息。

## 几个要注意的

**群里只理叫它的消息。** 两种算叫它：@ 了机器人，或者消息以 AstrBot 的唤醒前缀开头（默认 `/`，在 AstrBot 设置里改了的话跟着改）。`@机器人 /help` 和直接发 `/help` 都能用；只 @ 不带命令，比如 `@机器人 今天天气怎么样`，就交给大模型回。群里其他闲聊一概不理，不然一个几百人的群会把你的 token 烧光。想让它什么都回，把 `group_reply_needs_at` 关掉。

**自己发的消息不会触发机器人。** 你在手机上发的消息也会从事件流里过来，插件靠事件里的 `self` 字段把它们丢掉，否则机器人会自己跟自己聊起来。

**重启不会重放历史。** 第一次拉取从启动那一刻算起。

**发本地文件不需要任何额外配置。** AI 刚生成的图片、磁盘上的文件，插件会直接把字节传上去再发，不用 `callback_api_base`，也不用你有任何公网可访问的地址。已经是 http(s) 地址的图片则原样传过去，不多绕一趟。

**空轮询不推进游标。** 这条看着像实现细节，但它决定会不会丢消息：没拉到东西就等于什么都没确认，游标原地不动，下一轮重新问。

**同一条消息只回一次。** 插件记着最近处理过的 2000 条事件，就算同一条被拉到两次，也只交给机器人一次。

**不理微信团队、公众号和系统通知。** 「微信团队」会给任何发给它的话自动回一句「如果遇到问题，可轻触此处反馈给我」，机器人要是回它，两边就能一直互相回下去；公众号的自动回复也一样。所以这几类消息不会交给机器人：微信团队和其他微信自带的账号、`gh_` 开头的公众号、进群退群这类系统提示、撤回通知、好友申请。

**防止跟别的机器人互相回。** 朋友那边要是也开着自动回复，两个机器人能一直聊下去。插件会看同一个会话一分钟内触发了几次，超过 `loop_guard_per_minute`（默认 12 次）就先暂停 3 分钟不理这个会话，日志里会打一行提醒。真人一分钟很难发这么多条，所以正常聊天基本碰不到。

## 更新记录

**0.1.3（2026-09-27）** 修了群里 @ 机器人没反应的问题。

AstrBot 在群里只理两种消息：以唤醒前缀开头的，或者带着"@ 了机器人"标记的。插件以前把 `@ink /help` 整句当普通文字交过去，开头不是 `/`，也没有 @ 标记，AstrBot 就当没看见；机器人自己的 ID 还填成了实例号，就算有标记也对不上。另外不带 @ 的 `/help` 被插件自己挡掉了。
现在 @ 机器人会以 @ 标记交给 AstrBot，文字里的 `@ink` 去掉，机器人的 ID 用它的微信号；以唤醒前缀开头的群消息也会交过去。机器人在群里改了群昵称也认得出来。升级方法同下。

**0.1.2（2026-09-27）** 修了机器人跟「微信团队」来回聊个没完的问题。

微信团队会推一些系统通知（一串数字），插件以前当成普通消息交给了机器人，机器人回了一句，微信团队又自动回「如果遇到问题，可轻触此处反馈给我」，然后就停不下来了，有人 8 分钟里互发了 105 轮。
现在系统通知、微信团队、公众号的消息都不会交给机器人；另外加了防互相回的保护，同一个会话一分钟触发太多次会先暂停几分钟。升级方法同下。

**0.1.1（2026-09-27）** 修了发一条 `/help`、机器人每 3 秒回一遍停不下来的问题。

原因是游标没往前走：服务端以前只有一页取满才给 `next_cursor`，插件没拿到游标，就一直从启动那一刻重新拉，同一条消息每次都被当成新的。
服务端已经改了，插件这边也补了两道：没给游标就用这一页最后一条的 `event_id` 往前走；处理过的事件记下来，绝不回第二次。

升级：

```bash
cd data/plugins/astrbot_plugin_welink
git pull
```

然后在插件管理里重载，或者重启 AstrBot。

## 风险

微信的用户协议不允许非官方客户端，这类方案都有账号被限制的风险。触发风控的通常不是"用了接口"本身，而是**行为像机器**：秒回、高频、批量加好友、群发广告。用自己的号、做自己的事、控制频率。重要的号别拿来试。
